# X Post

## 用途

把一个观点、新闻、风险提醒或文章片段改写成适合 X/Twitter 的短内容。目标是获取阅读、转发、关注，但不牺牲事实边界和判断质量。

## 输入

- 原始内容
- 目标：曝光 / 关注 / 讨论 / 导流长文
- 受众：开发者 / 投资者 / 安全从业者 / crypto 用户 / 普通读者
- 是否有来源：有来源则保留来源；无来源则降级表达

## 改写原则

- 核心信条：我写的每一条，都要让看的人比刷到之前更清醒一点，而不是更冲动。
- 第一行必须有钩子：风险、反常识、具体行动、强问题四选一。
- 不要写“保持警惕”这种弱结尾，要给具体动作。
- 一条推文只讲一个核心判断。
- 多用短句，少用形容词。
- 用“你现在应该做什么”制造收藏/转发价值。
- 如果事实未核验，用“如果你...”或“这类事件提醒我们...”降级，不要直接扩大事实。
- 安全类内容优先写行动清单：rotate、revoke、audit、scan、least privilege。

## 写作戒律

- 具体打败抽象：不发“伟大灵魂”这种空话，每个观点至少落到一个标的、一个数字、一个案例或一个明确场景上。
- 翻译，不卖弄：每冒出一个行话（如 NAV、一级半、TVL、MEV、CI/CD），立刻用一句人话或一个类比解释它。
- 给逻辑，不给指令：可以说“我为什么这么看”，不说“快上车”。安全检查可以给操作清单，投资和情绪判断不给命令式结论。
- 敢认错：如果是复盘或此前看错，直接标出“我之前错在哪里”，不要把错误包装成“战略调整”。
- 钩子放前三行：X 上没人读铺垫，前三行必须让人知道为什么该停下来。

## 优先级

1. 事实边界高于传播。
2. 让读者更清醒高于制造情绪。
3. 具体案例高于宏大判断。
4. 人话解释高于术语密度。
5. 可信度高于短期互动。

```markdown

<一条可直接发的推文>

## 备选版本

2. <偏强钩子>
3. <偏开发者行动清单>

## Thread 版本

1/n ...

## 风险提示

- 哪些事实需要来源：
- 哪些表达可能夸大：
- 是否让读者更冲动而不是更清醒：
```

## 检查清单

- [ ] 第一行是否足够强？
- [ ] 是否有具体动作？
- [ ] 是否能被转发给同事？
- [ ] 是否避免了未经核实的恐慌表达？
- [ ] 是否有关注理由？
- [ ] 是否足够具体，而不是抽象口号？
- [ ] 是否把行话翻译成人话？
- [ ] 是否给了逻辑，而不是命令读者行动？
